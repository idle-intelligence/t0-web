## Divergence hunt

First run: patch-embedding matched the reference to ~3e-5 max-abs (expected float rounding), but layer-0 output jumped to ~5e-3 to ~8e-3, and the final quantiles to ~1.1e-3 to ~2.9e-3 — a real bug, not accumulated rounding, localized to layer 0's time-attention (the only new math between patch-embedding and layer-0-output).

Cause: `rotary_embedding_torch`'s xpos `scale` table and its `cos`/`sin` tables use **different duplication schemes** for the same half-width array. `cos`/`sin` interleave-duplicate (`repeat(freqs, '... n -> ... (n r)', r=2)` → `f0,f0,f1,f1,...`), matching `rotate_half`'s adjacent-pair convention. The xpos `scale`, computed separately in `RotaryEmbedding.get_scale`, duplicates via `torch.cat((scale, scale), dim=-1)` — **mirrored halves** (`s0,s1,...,s31,s0,s1,...,s31`), not interleaved pairs. The initial Rust port used interleaved duplication for `scale` too (copying the `cos`/`sin` pattern), which is wrong.

Fix: `crates/t0-core/src/ops.rs::RopeTables::new` now fills `scale[p*head_dim + j]` and `scale[p*head_dim + half + j]` from the same `s`, separately from the interleaved `cos`/`sin` fill. Regression test: `crates/t0-core/tests/ops_tests.rs::rope_scale_table_is_halves_concat_not_interleaved`.

## What's not covered by this milestone

- `FUTURE` covariate rows in the scaler (`crates/t0-core/src/scaler.rs` panics on them) — no fixture exercises them; only target/historical (causal) scaling is ported.
- Autoregressive rollout beyond `max_horizon=1024` (`crates/t0-core/src/model.rs::forecast` asserts against it).
- Quantile interpolation/extrapolation (`t0/quantile.py`'s `interpolate_quantiles`/`extrapolate_quantiles`) for requested quantile levels other than the 5 trained ones.
- Q8/Q4 quantization and the wgpu/WASM runtime path (only `cargo build --target wasm32-unknown-unknown` for `t0-core` is checked to compile in this milestone; no WGSL kernels, no browser page).
