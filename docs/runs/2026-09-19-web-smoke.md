# Web smoke test — one-signal instrument, WASM CPU (ndarray)

- Machine: Apple M2 (Darwin 25.3.0). GPU occupied by `llm-life train-a`
  throughout — WASM here is the CPU (`burn-ndarray`) backend only, no
  WebGPU (see `crates/t0-wasm/README.md`'s "not wired up" section).
- Commit: `58f9a36` (`t0-wasm` crate) + this run's `web/` and
  `scripts/headless/` additions.
- Browser: Playwright's bundled Chromium-for-Testing (`chromium-1229`,
  version 150.0.7871.24 reported by `browser.version()`), launched via
  `playwright` (added as a local `devDependency`, `package.json`) with an
  explicit `executablePath` — never the maintainer's real browser.
- Page: `web/index.html` served by `python3 web/serve.py --port 8031`.
- Model: `web/models/t0-alpha-q8_0.gguf` (Q8_0, 108,936,047 bytes — same
  file as `docs/BENCHMARKS.md`'s native Q8_0 latency row, copied from
  `/tmp/t0-alpha-q8_0.gguf`, this session's `t0-cli export-gguf` output).
- Series: `web/data/series.f32`, `tools/make_web_demo_series.py`'s
  deterministic synthetic 640-point series (not a real dataset — see that
  script's docstring for why).
- Command: `node scripts/headless/run.mjs --url http://127.0.0.1:8031/ --origins 200,400,560`

Gates checked per origin (`scripts/headless/run.mjs`): forecast length ==
`horizon * nQuantiles` (32*5=160), every value finite, and quantiles
monotone non-decreasing across the quantile index at every timestep
(t0-alpha's trained levels `[0.1, 0.25, 0.5, 0.75, 0.9]` are sorted, so a
correctly-wired decoder must preserve that order). All three origins
passed all three gates.

## Reading the numbers

- Page ready (WASM module fetch + model download + GGUF parse/dequant +
  tensor build + series fetch) in ~1.1s — all over loopback, so this is
  not a real-network download time, just a correctness/wiring check.
- Per-forecast latency (context capped at 512, horizon 32, same shape as
  `docs/BENCHMARKS.md`'s native CPU latency table): 556-834 ms in the
  browser's single-threaded WASM vs 363-424 ms native (ndarray, 8 threads)
  for the same quant (Q8_0) — see `docs/runs/2026-09-19-latency-cpu.md`.
  Slower is expected: `burn-ndarray`'s matmul path and this crate's build
  have no WASM SIMD/threading enabled yet, and native ndarray gets to use
  all 8 logical cores. Not investigated further this session (out of
  scope: WebGPU is the intended fast browser path, not a faster CPU-WASM
  build — see `crates/t0-wasm/README.md`).
- Latency rises with origin (556 -> 678 -> 834 ms) because context length
  grows with origin up to the 512 cap (`ctxStart = max(0, origin - 512)`,
  `web/worker.js`) — origin 200 has only 200 context steps, origin 560 has
  the full 512-step cap. Expected, not noise.

## What was not run

WebGPU/wgpu in the browser — GPU was occupied by `llm-life train-a` for
the whole session (this run's hard constraint), and the `wgpu` backend for
`t0-wasm` isn't wired up end-to-end yet regardless (sync `into_data()`
readback hazard, see `crates/t0-wasm/README.md`).
